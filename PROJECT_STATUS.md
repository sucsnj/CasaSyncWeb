# Estado do Projeto — CasaSync Web

## Status Atual
- **Foco:** Migração SWR/Local-First — **Fases 0, 1 e 2 concluídas**.
  - **Fase 0 (P0/pré-requisitos):** SW resiliente (`CACHE_NAME` v5, install all-or-nothing corrigido, poda FIFO); `public/manifest.webmanifest` duplicado removido (o do App Router ficou correto); `NativeServiceWorkerGuard` no root layout; `AndroidBackButton` deduplicado; logout revoga push + `window.location.replace('/login')`; `error.tsx`/`not-found.tsx`; órfãos `@tanstack/*`/`idb-keyval` removidos manualmente (não constavam no lockfile); versões corretas instaladas na Fase 1.
  - **Fase 1 (Infraestrutura):** `@tanstack/react-query` + `@tanstack/react-query-persist-client` + `idb-keyval`; provider global (`src/app/providers.tsx`) com cache persistido em IndexedDB (`casasync:qc`, buster `casasync-v1`, sem persistir `comunicados`/`punishments`); chaves por tenant (`src/lib/query/keys.ts`); purger por conta (`SessionCachePurge` + `casasync:last-user`); logout limpa cache + IndexedDB.
  - **Fase 2 (Rotas críticas):** leituras extraídas para `src/actions/*-reads.ts` (`tasks/rewards/achievements/chest/notifications`) com autorização por sessão (`assertHouseAccess`, `src/utils/tenant-scope.ts`); `/tasks`, `/rewards` (saldo de pontos incluso — `useProfilePoints` removido), `/achievements`, `/chest` e sino de notificações migrados para o query cache; Realtime → invalidação/patch no cache (sem mais sync effects).
  - **Fase 2.1 (Navegação 0ms):** `page.tsx` das 4 rotas virou shell estático sem `await` (sem `force-dynamic`); shell `(app)` monta `AppSessionProvider` (`src/components/session/app-session.tsx`) com `{ userId, role, houseId, houseName }`; screens em `src/components/screens/*`; bundles agora carregam settings (deadlines/decaimento/anexos/texto/recompensas/pontos/janelas de resgate); `loading.tsx` desses segmentos removido; `<PageSkeleton />` só quando `isPending && !data` (1ª visita) e `<QueryError />` com retry em falha.
- **Pendente:** Fase 4 — avaliar Cache Components (ADR própria) e ADR-0029 (TanStack + IndexedDB por tenant).
  - **Fase 3 (Saneamento):** removidas as leituras RSC das ações para as rotas que viraram shells no cliente; `HOUSE_CONTEXT_ROUTES` reduzida a rotas RSC; shell estático montado em `(app)/layout.tsx` sem `await` nem `cookies()`; `AppSessionProvider` com `{userId, role, houseId, houseName}` lido no cliente; banner offline; `PageSkeleton`/`QueryError` no cliente.
  - **Decisão registrada:** as telas migradas mantêm o padrão `useOptimisticAction` + TanStack Query para o optimistic UI (patch no bundle + Realtime → invalidação). A padronização via `useMutation` por item foi deixada para a Fase 3.1 com trocar todos os call-sites das 24 bordas de lista de propósito e cobertura de testes — o risco/benefício hoje é negativo.
- **Tarefas Pendentes:** Fase 4 (Cache Components + ADR-0029) e Fase 3.1 (se desejado).
